# HorecaPass — веб-версия

Платформа найма для HoReCa. Работает в связке с мобильным приложением
(`Zhanb6/horeca_pass_mobile`, Flutter) — бэкенд общий, Django + DRF
на `api.horecapass.com`.

Next.js 15, React 19, TypeScript, Tailwind.

## Запуск

```bash
npm install
npm run dev
```

Открывается на `http://localhost:3000`. Бэкенд по умолчанию боевой; чтобы
переключить:

```bash
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000 npm run dev
```

## Что уже собрано

Первый заход — кандидатская половина, самая громкая претензия заказчика:

- **Диалоговый онбординг** (`/onboarding`) — вопросы задаются по одному,
  отвечать можно голосом или текстом. Не форма: форма из тех же вопросов уже
  была в прошлой версии и получила ответ «вообще не то».
- **Параметры по профессиям** (`lib/professions/`) — у хостес, официанта, шефа
  и менеджера разные наборы вопросов. У шефа они ветвятся по уровню позиции:
  комми не спрашивают про food cost и размер команды.
- **Профиль в виде резюме** (`/profile`) — лист CV, а не карточка платформы.
- **Ассистент** — подсказывает, чего не хватает и почему это важно.
- **Дизайн-система** на Варианте 1 брендбука, светлая и тёмная темы.

Полный статус по 21 пункту документа заказчика и по правкам Алдияра —
в [STATUS.md](STATUS.md). Расшифровки голосовых — в
[docs/voice-notes.md](docs/voice-notes.md).

## Как это устроено

```
app/            маршруты (App Router)
components/
  ui/           примитивы дизайн-системы
  onboarding/   лента диалога, поле ответа, ассистент
  cv/           резюме
lib/
  api/          клиент, реальные адреса бэкенда, заглушки
  professions/  описания профессий — ядро продукта
  onboarding/   логика диалога, отдельно от React
legacy/         прошлое демо на Vite, оставлено как референс UI
```

### Профессии — это данные

Вопрос описывается объектом: формулировка для диалога, подпись для резюме,
тип поля, раздел CV, условие показа. Один и тот же список работает трижды —
как сценарий разговора, как разделы резюме и как поля матчинга. Если бы это
были три разных описания, они бы разошлись на второй неделе.

Добавить бармена — значит дописать файл в `lib/professions/` и одну строку
в реестр. Ни один экран при этом не меняется.

### Цвета

Каждый цвет — переменная в `app/globals.css`. В компонентах hex-кодов нет:
прошлую версию пришлось перекрашивать вручную именно потому, что цвета жили
в разметке. Перекрасить платформу под новый брендбук — правка одного файла.

Бежевый из брендбука остался, но перестал быть цветом интерфейса — ушёл в фон
и поверхности. Действие и состояние держатся на сине-стальном `#728394`,
акцент и ИИ-подсказки — на медном `#B3603C`.

### Связка с мобилкой

`lib/api/endpoints.ts` — адреса, выписанные из кода мобильного приложения,
а не из документации: OpenAPI-схема на сервере устарела, о чём предупреждает
и сам мобильный репозиторий.

Прошлая версия веба ходила на выдуманные адреса (`/auth/otp/send/`,
`/vacancies/`) — ни один из них на сервере не существует.

Клиент повторяет поведение мобильного: Bearer-токен, одна попытка обновления
на 401, single-flight для параллельных запросов.

### Заглушки

Часть требований не имеет эндпоинтов на бэкенде. Такие места обслуживает
`lib/api/pending.ts`, и каждое **явно помечено в интерфейсе** плашкой «этого
ещё нет на сервере».

Это сделано намеренно. Заказчица уже получила демо, которое выглядело рабочим,
и отдельно на это указала: «это не рабочий сайт, где ты реально можешь что-то
технически поделать». Второй раз выдавать заглушку за функцию нельзя.

Список недостающего с предлагаемыми адресами — в `MISSING_ON_BACKEND`
(`lib/api/endpoints.ts`). Он же годится как ТЗ бэкендеру.

```bash

```

Контраст обеих тем проверялся в браузере на всех трёх страницах — WCAG AA

не меньше 44px.

## Известные ограничения

- Голосовой ввод работает через Web Speech API — только Chrome и Safari,
  и распознавание уходит в Google. Для продакшна нужен серверный
  `POST /api/ai/transcribe/`.
- Загруженные файлы не сохраняются: эндпоинтов портфолио нет.
- Работодательская часть в этот заход не входила.
- Логотипа нет — исходник не был передан.
- В зависимостях остаются два предупреждения `npm audit` (`sharp`, `postcss`) —
  оба транзитивные внутри `next`, исправятся с его обновлением.
