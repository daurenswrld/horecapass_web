# HorecaPass — веб-версия

Десктопная версия мобильного приложения (`Zhanb6/horeca_pass_mobile`, Flutter).
Те же экраны, та же логика, тот же бэкенд — Django + DRF на `api.horecapass.com`.
Аккаунт общий: вошли в приложении — вошли и здесь.

Next.js 15, React 19, TypeScript, Tailwind.

## Запуск

```bash
npm install
npm run dev
```

`http://localhost:3000`.

**Демо-вход.** В `npm run dev` на странице `/login` есть кнопки «As a candidate»
и «As an employer» — вход без аккаунта на боевом сервере (`lib/demo/session.ts`).
Закрытые запросы отвечаются локально, публичные вакансии берутся с сервера
анонимно, токены не отправляются. В обычной сборке кнопок нет; для превью-деплоя
их можно включить переменной `NEXT_PUBLIC_DEMO_AUTH=1`.

Другой бэкенд:

```bash
API_ORIGIN=http://localhost:8000 npm run dev
```

## Что работает

- **Вход и регистрация** — по-настоящему, против боевого сервера. Пароля нет:
  почта → шестизначный код письмом, как в мобилке. Роль (`APPLICANT` /
  `COMPANY_OWNER`) определяет, куда попадёт пользователь после входа.
- **Вакансии соискателя** — список из `/api/vacancies/`, вкладка «Для вас»
  из `/api/vacancies/matches/`, поиск, отклик, сохранение в избранное.
- **Вакансии работодателя** — список из `/api/vacancies/my/`, активные
  и архивные.
- **Отклики соискателя** — `/api/applications/my/`: статусы воронки, визовый
  этап, состояние видео-презентации.
- **Чаты обеих ролей** — история по REST, живые сообщения вебсокетом,
  заготовки ответов у компании. Голосовые слушаются; запись оставлена
  приложению.
- **Тёмная тема** — три состояния.

## Разделы с правками заказчика

По ним бэкенда нет, поэтому они собраны как показ замысла: данные лежат
в браузере, и на каждом экране стоит плашка `DemoNotice` — с тем, что именно
не работает и какой эндпоинт нужен. Заказчица уже получала демо, выглядевшее
рабочим, и отдельно на это указала; повторять это нельзя.

- **Профиль** — анкета идёт разговором (голосом или текстом), набор вопросов
  зависит от профессии, на выходе лист резюме, а не карточка платформы.
  Движок профессий — `lib/professions/`: хостес, официант, шеф, менеджер,
  с ветвлением по уровню позиции. Перед публикацией — согласие с подписью
  от руки (требование заказчицы от 17.09).
- **Подбор** — список кандидатов и перевод по этапам настоящие; корзина
  и массовые действия показаны, но выполняются локально.
- **Онбординг работодателя** — `/company/onboarding`, по утверждённому
  редизайну: Setup your company с живой карточкой, Complete your company
  profile, ветка pre-opening, Smart vacancy (разговор вместо формы по Vacancy
  Prompt заказчицы), правка деталей (What you offer, Responsibilities, Hiring
  process), превью со Smart vacancy review, Agreement & Policies с подписью
  и лицензией, тарифы (бриф работодателя, пункт 14).
  Ассистент — сценарий в браузере (`lib/demo/employer.ts`), черновик
  сохраняется после каждого шага. Вход — приглашение на экране Jobs.
  При настоящем входе (не демо) профиль компании уходит в
  `PATCH /users/api/users/me/company/`, а вакансия — черновиком (status DRAFT)
  в `/api/vacancies/my/` и видна в «Drafts» на экране Jobs
  (`lib/demo/employer-sync.ts`). Новые поля компании — ветка бэкенда
  `feat/company-onboarding-fields`; до её выкатки сервер их игнорирует.
  В браузере пока остаются фото заведения, PDF, подпись и лицензия — для них
  на сервере нет загрузки. Команда в Settings — настоящие приглашения.

- **Онбординг кандидата** — `/onboarding`, по брифу кандидата (22.09): where
  you're based (автокомплит национальности), CV и материалы, страны работы,
  Smart-проверка профиля, предложение CV upgrade с превью «до/после»,
  согласие с подписью, квалификация (роль и стаж; сами 8 вопросов генерирует
  сервер — банк вопросов заказчицы в код сайта намеренно не входит; кухня
  квалификацию пропускает) и видео-визитка. Шаблон резюме — `components/cv/cv-template.tsx`.
- **Профиль кандидата** — карточка личности, прогресс готовности (тот же, что
  в ленте вакансий), список «My Profile», References.
- **Вакансия** — фото заведения в шапке, «Prepare for interview with AI»
  (приватная тренировка). Зарплата min = max показывается одним числом,
  в карточке — перки вместо общих навыков.
- **Communities** — второй сегмент в чатах кандидата: правила, кличи
  по национальности и стране, группа от двух участников, ссылки и телефоны
  блокируются.

Что нужно от бэкенда, перечислено прямо на экранах и в `MISSING_ON_BACKEND`
(`lib/api/endpoints.ts`).

## Как устроено

```
app/
  backend/[...path]/  прокси к api.horecapass.com
  (app)/              разделы после входа: боковая навигация + контент
  login, register     вход и регистрация
components/
  auth/               форма входа, ввод кода
  shell/              каркас, навигация, шапка раздела
  vacancy/            карточка и подробности вакансии
  ui/                 примитивы дизайн-системы
lib/
  api/                клиент, адреса, авторизация, вакансии
  auth/               кто вошёл, куда его вести
```

### Цвета

`app/globals.css` — палитра утверждённого редизайна в Figma (тёмно-коричневые
кнопки `#502D12`, тёмно-синие заголовки `#06213A`, персиковый фон). До него
это был построчный перенос `lib/core/theme/app_colors.dart`; имена токенов
остались мобильные (`background`, `surfaceMuted`, `accent`, `onAccent`…),
чтобы при переносе экрана не держать в голове таблицу соответствий. Меняется
палитра — правится этот файл, и только он.

### Прокси к бэкенду

Браузер не может ходить на `api.horecapass.com` напрямую: у мобильного
приложения нет origin и CORS его не касается, у браузера — касается. Все
запросы идут через `/backend/*` на своём же сервере.

Обработчик, а не `rewrites`, по двум причинам, обе выяснились на практике:

1. Next отвечает 308 на путь с завершающим слэшем и уводит на вариант без
   него — а все маршруты Django заканчиваются слэшем (лечится
   `skipTrailingSlashRedirect`).
2. Django стоит за nginx с редиректом на HTTPS и смотрит на `X-Forwarded-Proto`.
   Через `rewrites` туда уезжало `http`, и сервер отвечал 301 на самого себя.
   `rewrites` не дают управлять заголовками, обработчик — даёт.

### Адреса бэкенда

`lib/api/endpoints.ts` — выписаны из кода Flutter-приложения, а не из
документации: OpenAPI-схема на сервере устарела, о чём предупреждает и сам
мобильный репозиторий. Прошлая версия веба ходила на выдуманные адреса
(`/auth/otp/send/`, `/vacancies/`) — ни одного из них на сервере нет.

Клиент повторяет поведение мобильного `ApiClient`: Bearer-токен, одна попытка
обновления пары на 401, single-flight для параллельных запросов.

## Проверки

```bash
npm run typecheck
npm run build
```

Разбор вакансий проверялся на реальном ответе сервера. Круг «браузер → прокси →
Django → интерфейс» проверен на входе: сервер возвращает свою ошибку, и она
видна в форме.

## Ограничения

- Токены лежат в `localStorage`. Так же поступает мобилка (`SharedPreferences`),
  но на вебе это ещё и означает доступность из JS на странице. Правильнее
  httpOnly-куки, для этого нужна ручка на бэкенде.
- Вебсокет чата подключается к серверу напрямую, минуя прокси, — туннелировать
  вебсокеты через обработчик Next нельзя.
- Логотипа нет: заказчица говорит, что он разработан и выглядит иначе, но файла
  среди переданных материалов не было. Заглушка — в `components/brand.tsx`,
  меняется одним файлом.
